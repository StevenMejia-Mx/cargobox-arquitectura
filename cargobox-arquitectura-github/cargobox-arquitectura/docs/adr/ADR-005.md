# ADR-005: Service Layer delgada con cuatro Application Services por área del negocio

| Campo | Contenido |
|---|---|
| Título | Service Layer delgada con cuatro Application Services por área del negocio |
| Estado | Aceptada (2026-10-14) |
| Contexto | La tarea pide Application Services con un método por caso de uso y sin lógica. Había dos propuestas: una clase Handler por caso de uso (propuesta de la IA) y servicios agrupados por área (propuesta del equipo). |
| Alternativas | Un Handler por caso de uso (cinco clases); un solo servicio con todos los métodos. |
| Decisión | Cuatro servicios y cinco métodos: EnvioApplicationService (US01), RastreoApplicationService (US04), EntregaApplicationService (US05 y US06, mismo actor y misma Guía) y ConsultaRastreoQueryService (US09). Cada método abre y cierra su propia transacción. |
| Consecuencias | (+) Usa el término «Application Services» de la tarea, agrupa por actor y deja claro qué orquesta cada servicio. (−) Un servicio con dos métodos puede crecer; si EntregaApplicationService pasa de tres casos de uso se divide. |
| Trazabilidad | US01, US04, US05, US06, US09; RN-01 a RN-08; Tablas 9 a 13 |
