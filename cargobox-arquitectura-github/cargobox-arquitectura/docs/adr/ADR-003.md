# ADR-003: CQRS básico: comandos y consulta separados

| Campo | Contenido |
|---|---|
| Título | CQRS básico: comandos y consulta separados |
| Estado | Aceptada (2026-10-12) |
| Contexto | US09 necesita una línea de tiempo plana de eventos; no cambia el estado ni aplica reglas. Reducir llamadas a Atención al Cliente (TR-01) depende de que esta consulta sea completa y rápida. |
| Alternativas | Un solo servicio con métodos de lectura y escritura sobre el agregado; bases de datos separadas para lectura y escritura. |
| Decisión | Los casos que cambian el estado reciben un Command y los atienden EnvioApplicationService, RastreoApplicationService y EntregaApplicationService. La consulta US09 la atiende ConsultaRastreoQueryService, que lee con HistorialRastreoReader y devuelve HistorialEnvioView; la proyección escribe con HistorialRastreoWriter a partir de los Domain Events. Ambos lados comparten la misma base de datos MySQL. |
| Consecuencias | (+) La vista de lectura no contamina el modelo de dominio y la consulta no abre transacción de escritura. (−) Hay que mantener la proyección del historial; consistencia eventual de pocos segundos. |
| Trazabilidad | US09 (y US08 en el trabajo final); RN-08; TR-01 |
