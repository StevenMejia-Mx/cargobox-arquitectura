# ADR-004: Domain Events para notificar y actualizar el historial

| Campo | Contenido |
|---|---|
| Título | Domain Events para notificar y actualizar el historial |
| Estado | Aceptada (2026-10-12) |
| Contexto | US05 pide notificar al destinatario tras un intento fallido y el resguardo; el remitente debe ver cada movimiento. El dominio no debe depender de correos ni de la base de lectura. |
| Alternativas | Que cada Application Service llame directamente al notificador y actualice el historial. |
| Decisión | La Guía registra eventos (GuiaGenerada, EscaneoRegistrado, IntentoEntregaFallido, GuiaEnResguardo, EntregaCompletada). Después de confirmar la transacción, el servicio los entrega a PublicadorEventos, que los despacha a NotificacionHandler y a HistorialRastreoProjection. |
| Consecuencias | (+) Agregar nuevas reacciones (alertas de 24 h, US12) no cambia la Guía ni los servicios. (−) Si la publicación falla después de confirmar, el evento debe reintentarse (patrón Outbox en el trabajo final). |
| Trazabilidad | US05, US06, US09; RN-05, RN-06; TR-01, TR-02 |
